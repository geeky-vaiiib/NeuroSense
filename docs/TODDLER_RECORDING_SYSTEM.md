# Separate toddler recording system

Scope: Q-CHAT-10, ages 18–24 months, with optional caregiver-supervised recording measurements. This is a toddler-specific workflow and backend policy, not a child/adult model selected under a different label.

- Questionnaire: the existing official Q-CHAT-10 server scoring and separate toddler cohort model remain unchanged.
- Gaze: `ToddlerGazeMeasurements`, pipeline `toddler-measurements-v1`, operates directly on OpenFace timestamp/confidence/success/gaze/head columns. It never loads DASD weights, fitted head coefficients, normalization, window representations or domain references. Reports degrees of movement and observed tracking availability. Engineering hygiene: finite columns, tracking confidence >=0.8, successful detection, increasing adjacent timestamps; >=2 retained frames, positive retained duration and >=50% retained frames. Continuity is the fraction of adjacent retained gaps <=0.25s. Quality indicator is usable-frame fraction, not model confidence. These thresholds are not validated toddler developmental/clinical criteria. No fixation, screen position, eye contact or ASD classification is inferred.
- Face: toddler policy calls shared decoding/detection/image-quality utilities with expression inference disabled. Reusing pixel processing is not reusing adult CNN weights. No toddler expression classifier is installed.
- Voice: toddler policy calls shared decoding and acoustic measurement utilities with an early return before either ASD or emotion classifier loading. No toddler speech classifier is installed. Speech duration/acoustic feature definitions are technical collection requirements, not evidence of developmental norms. Caregivers must not substitute their own voice.

From toddler answer review, choose **Add or retry optional recordings**. The sequence is toddler gaze -> natural vocalisations -> facial snapshot -> review. Camera/microphone require user interaction. Each step can be skipped; never force participation. Captured inputs and accepted gaze job references stay in owner-scoped in-memory drafts for submission retry. Unsaved reload still loses drafts, as documented for existing workflows. The questionnaire-only path remains available. Recordings do not change the Q-CHAT-10 result.

Gaze upload declares `population=toddler`. Its background job selects the dedicated service before obtaining any child/adult gaze service. Toddler submission rejects any gaze result not stamped as toddler processing by the server. Auth, ownership, durable leases, raw-file cleanup and terminal race protection use the existing shared job infrastructure. Infrastructure reuse does not mix population models. Unsupported toddler classifier outputs remain null, with scope/reason stored in the same versioned backend report consumed by UI/PDF/history. Historical cases are never reprocessed.

Tests: independent numeric gaze fixture proves no checkpoint/domain call; generated audio proves the ASD classifier loader is not called; controlled face/detector and audio boundaries verify API/storage/reopening with all three measurements and null predictions; adult-job attachment rejected; component integration verifies all captured inputs are sent without skip flags. These are engineering tests, not physical toddler participation, clinical validation or developmental norms.

Remaining dependency for toddler-trained predictions: appropriately licensed toddler participant-level recordings with target-label provenance, matching ages/task/devices/languages, participant-independent splits and a prespecified evaluation protocol. No such trained recording models are present. No adult/child model, synthetic diagnosis, new training, participant download or fusion was substituted.
