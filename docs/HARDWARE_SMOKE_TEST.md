# Separate real-service smoke test — not executed in this review

Run only with approved consent/rights/retention arrangements. Use a dedicated research database (or disposable local in-memory mode) and a matching frontend/API hostname, on HTTPS or localhost. Do not use a child participant merely to validate capture plumbing; an appropriately consenting adult operator can test technical capture without supporting population-validity claims.

1. Confirm locked runtime, FFmpeg/ffprobe, trusted OpenFace FeatureExtraction version/image digest and architecture; record these plus browser/OS and artifact hashes. Verify `/ready`, `/`, `/gaze/status`. Do not confuse installed model with available OpenFace.
2. Register/login, refresh a protected URL, verify saved-user session; select each age track and verify unsupported ages are explained. For AQ-10 use independently hand-scored answers around totals 5/6/7; for toddler around 2/3/4 including reversed Q10. Compare server, saved history, result, explanation and downloaded PDF. A technical adult camera check is not a toddler model validation.
3. Deny camera permission, verify announced error, retry with permission, then skip and verify explicit skip status. Permit camera, perform full 30-second gaze task, upload and observe actual processing stages. Poll from a separate backend worker connected to the same throw-away MongoDB if conducting a cross-process integration smoke (do not claim globally shared throttling/slots). Verify completed vs poor-quality vs out-of-domain outcomes, null withheld output and exclusion from result.
4. Deny microphone, retry, capture actual 20-second speech, listen to the sample, then explicitly continue or skip. Confirm measured pitch/energy/voicing fields and unavailable classifier. Test silence/unvoiced input: pitch null with explicit status. No transcript-derived or acoustic ASD classifier should appear.
5. Deny then permit facial capture. Test no face, blur/low light and a usable image. Verify detection/quality only and no fabricated expressions or ASD score.
6. Interrupt network during upload/polling/submission. Inspect retry/skip and retained answers. Reuse the same screening submission key after a lost response and verify exactly one saved case. Browser polling timeout is not computation cancellation. Check another user's case/job returns 404, logout revocation and session expiration.
7. Inspect raw/intermediate spool before, during and after successful/failed/rejected processing. In isolated storage kill/restart the backend; wait for lease expiry and verify abandoned status, late-completion rejection and stale-file cleanup policy. Record any files retained until process return or startup sweep.
8. Test keyboard-only Back/Next/answer editing and focus, screen-reader announcements, mobile viewport/landscape, real download rendering including supported name characters. Verify no stale/synthetic success after unavailable services. Report real-service coverage separately from mocked/component tests, with actual counts and observed defects.

Expected release evidence: dated reproducible transcript and screenshots/PDF inspections with no participant-identifying data, resource measurements at the configured concurrency, exact environment/model/tool versions, cleanup evidence, and explicit operational limits. Passing this technical test does not establish clinical validity or deployment permission.
